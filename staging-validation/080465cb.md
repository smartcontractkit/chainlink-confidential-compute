# Staging validation: priv-724-732-metric-buckets-request-kind

## Change

Capability plugin: duration histograms forwarded through `MetricsEmitter`
(capability-side and enclave-forwarded `*_duration`) use explicit buckets from
5ms to 300s instead of the OTel defaults (0, 5, 10, 25, 50... seconds).
Host: confidential-http executions now carry `request.kind="action"` on the
host execution metrics, so the Enclave Hosts dashboard's Request Kind variable
covers HTTP. The host's enclave memory poll interval (default 5s) can be set
with `ENCLAVE_MEMORY_POLL_INTERVAL` (a Go duration such as `10s`).

## Validation steps

1. After the capability plugin rolls to staging, list the bucket bounds:
   `count by (le) (confidential_workflows_1_0_0_alpha_app_execution_completed_duration_bucket{platformEnv="staging-testnet"})`
2. On the Confidential Compute dashboard (staging), check App Execution
   Latency, GetSecrets Latency, Signature Verification Latency and Shares
   Combining Latency for both capabilities.
3. After the host image rolls to staging:
   `count by (app_id, request_kind) (confidential_compute_enclave_execution_duration_seconds_count{deployment_environment="stage"})`
4. On the Enclave Hosts dashboard, select Request Kind = `action` and confirm
   the HTTP panels populate.
5. Host startup logs show `polling enclave memory` with `interval=5s`, or the
   configured value if `ENCLAVE_MEMORY_POLL_INTERVAL` is set.

## Success criteria

- Step 1 returns `le` values 0.005 through 300 plus `+Inf` (21 buckets) for
  series from upgraded nodes.
- Workflow app execution and GetSecrets P99 move off the 10s/25s bucket edges
  and track real latency; Signature Verification and Shares Combining read
  about 5ms or less instead of a flat 0.
- Step 3 shows `request_kind="action"` for `confidential-http@1.0.0-alpha`
  alongside the existing workflow kinds.

## Edge cases and risks

- While nodes run mixed plugin versions, `histogram_quantile` sums old and new
  bucket sets, so quantiles can look jagged until every node is upgraded.
- 21 buckets instead of 16 adds about 30% more bucket series per histogram.
- The enclave still rounds durations to 10ms, so sub-5ms steps stay
  indistinguishable from 0; that rounding is intentional and unchanged.
- Adding `request.kind` to HTTP host series starts new series once (no
  dashboard queries depend on its absence).
- An invalid or non-positive `ENCLAVE_MEMORY_POLL_INTERVAL` stops the host at
  startup. Unset keeps the current 5s; a very short interval polls the enclave
  back to back over vsock.
- Roll back if host export errors or cardinality alerts appear.
