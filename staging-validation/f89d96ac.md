# Staging validation: ci-publish-us-east-2-stage

## Change

CI only: adds the us-east-2 staging account `008732161165` to the image push
matrices in the nitro enclave, host and config-tracker build workflows. Nothing
deployed changes, and no image is built differently.

## Validation steps

1. On this PR, confirm the `staging-validation` check passes with this file
   present.
2. After merge, watch the next release-branch push (or `deploy-images` PR run)
   and confirm the `push-images` / `push-image` jobs list a
   `(008732161165, us-east-2)` leg for each app and that it succeeds.
3. In the target account, confirm the new tags exist:
   `aws ecr describe-images --registry-id 008732161165 --region us-east-2 --repository-name containers/enclave --query "sort_by(imageDetails,&imagePushedAt)[-1].imageTags"`

## Success criteria

- The publish run has a green us-east-2 stage leg for every app.
- `enclave-sha-*`, `enclave-workflows-sha-*`, `host-sha-*` and
  `on-chain-config-tracker-sha-*` resolve in
  `008732161165.dkr.ecr.us-east-2.amazonaws.com/containers/enclave`.
- The us-east-2 stage cluster pulls those tags without `ImagePullBackOff`.

## Edge cases and risks

- If the CI role or the `containers/enclave` repository is missing in
  `008732161165`, only that leg fails; `fail-fast: false` leaves the other
  accounts untouched.
- Applying `deploy-images` to a PR publishes PR-head `sha-*` tags, not release
  tags; release-branch pushes remain the source of deployed tags.
- The additions are per-account `include` entries, matching the existing
  fully-enumerated matrix layout.
