# Staging validation: redact-http-errors

## Change

Confidential HTTP and Confidential Workflows replace outbound HTTP errors with
fixed diagnostics before they leave the enclave. Response-close errors are no
longer logged. Both applications require updated trusted enclave images.

## Validation steps

### Prerequisites

Both trusted images must contain this fix. Required: approved staging deployment
and UI/log/telemetry access, Go 1.27.3, jq, rg, and CRE/1Password CLIs. Follow the
[canary setup](https://github.com/smartcontractkit/chainlink-deployments/blob/472afa46e90853025374948031471237792919d0/domains/cre/pkg/workflows/canary/README.md)
for the account/environment file. Confirm staging and `CRE_CLI_DON_FAMILY=zone-a`
(the target name alone does not select the DON family); its TEE region is us-west-2.
Set `TRIGGER_GATEWAY_URL` to the operator-provided **staging zone-a HTTP-trigger
gateway HTTPS URL**, not an enclave/relay endpoint. The route must already be enabled.
Do not replace canaries or change shared gateway, signer, enclave, or attestation settings.

### Set up once

Use the [redaction workflow](../tests/e2e/testdata/workflow/redaction/main.go),
started manually by the [HTTP-trigger command](../tests/e2e/cmd/http-trigger/main.go).
Signed input is only `{"case":"redirect"}` or `{"case":"certificate"}`. The workflow
validates it and selects a fixed URL; no Vault access or request-value logging.
`confidential-http` uses a normal handler calling the standalone capability;
`confidential-workflows` uses `HandlerInTee` with `SendRequestInTee`. Each trigger
starts one GET with `Authorization: Bearer cc-redaction-smoke`, no body or custom
CA (normal DON/enclave replication still applies):

- `redirect`: `https://httpbingo.org/redirect-to?url=https%3A%2F%2Fexample.com%2Fcc-redaction-smoke%3Ftoken%3Dcc-redaction-smoke`
  returns 302 with `Location: https://example.com/cc-redaction-smoke?token=cc-redaction-smoke`.
- `certificate`: `https://wrong.host.badssl.com/cc-redaction-smoke?token=cc-redaction-smoke`
  must fail certificate hostname verification.

Do not repoint the existing Infura canaries at these endpoints: they attach real
credentials. Do not use `tests/enclave_test.go` with `REMOTE_ENCLAVE_URL` against
shared staging: its helper rewrites enclave signer configuration.

Set `CC_REPO` and `CLD_REPO` to this checkout and a chainlink-deployments checkout.
Set `EVIDENCE_DIR` outside the disposable project. Run setup in an interactive shell.
Only the disposable signer's public address enters this workflow's config; its key
stays in a new mode-0600 file. Never reuse a deployment key, fund this key, or export it.

```bash
mkdir -p "$HOME/tmp"
mkdir -p "${EVIDENCE_DIR:?set a persistent evidence directory}"
SMOKE_ROOT=$(mktemp -d "$HOME/tmp/cc-redaction.XXXXXX")
(cd "$CC_REPO/tests" && GOTOOLCHAIN=go1.27.3 GOMAXPROCS=1 TMPDIR="$SMOKE_ROOT" GOTMPDIR="$SMOKE_ROOT" go build -mod=readonly -p 1 -o "$SMOKE_ROOT/http-trigger" ./e2e/cmd/http-trigger)
AUTHORIZED_KEY=$("$SMOKE_ROOT/http-trigger" -init-key -key-file "$SMOKE_ROOT/trigger.key")
cd "$CLD_REPO"
TMPDIR="$HOME/tmp" source domains/cre/cmd/canary_setup.sh --env staging
cre_staging whoami
mkdir "$SMOKE_ROOT/smoke"
cp domains/cre/pkg/workflows/canary/project.yaml "$SMOKE_ROOT/project.yaml"
cp "$CC_REPO/tests/e2e/testdata/workflow/"{go.mod,go.sum} "$SMOKE_ROOT/smoke/"
cp -r "$CC_REPO/tests/e2e/testdata/workflow/redaction" "$SMOKE_ROOT/smoke/"
cd "$SMOKE_ROOT"
```

### Deploy once per app

Run this section with `APP=confidential-http`, invoke and check both cases below,
then delete that workflow. Repeat with `APP=confidential-workflows`: two deployments,
four separate executions. Keep each generated name/ID for evidence and cleanup.

```bash
APP=confidential-http
NAME="cn_redaction_$(date -u +%m%d%H%M%S)"
jq -n --arg app "$APP" --arg key "$AUTHORIZED_KEY" '{app: $app, authorizedKey: $key}' > smoke/config.json
cat > smoke/workflow.yaml <<EOF
staging-zone-a:
  user-workflow:
    workflow-name: "$NAME"
  workflow-artifacts:
    workflow-path: "./redaction"
    config-path: "./config.json"
    secrets-path: ""
EOF
unset WORKFLOW_ID
TMPDIR="$HOME/tmp" GOTOOLCHAIN=go1.27.3 GOMAXPROCS=1 GOFLAGS='-p=1 -mod=readonly' cre_staging workflow deploy smoke --target=staging-zone-a
```

The wrapper pins CRE CLI v1.37.0, which deploys new workflows as active. Confirm
activation in the [staging UI](https://staging-cre-ui-cll.vercel.app/cre/discover)
and set `WORKFLOW_ID` to the ID printed by this deployment. Nothing runs on a schedule.

### Invoke and check each case

Run this section first with `CASE=redirect`, then with `CASE=certificate`, without
redeploying. Send one trigger per case:

```bash
: "${WORKFLOW_ID:?set the newly deployed workflow ID}"
: "${TRIGGER_GATEWAY_URL:?set the approved staging HTTP-trigger endpoint}"
CASE=redirect
unset EXECUTION_ID
TRIGGER_START=$(date -u +%FT%TZ)
"$SMOKE_ROOT/http-trigger" -key-file "$SMOKE_ROOT/trigger.key" -gateway "$TRIGGER_GATEWAY_URL" -workflow-id "$WORKFLOW_ID" -case "$CASE"
```

The helper signs `workflows.execute` with `CreateRequestJWT`, as in
`tests/e2e/e2e_test.go`'s `sendHTTPTrigger`, binding the workflow ID and case. It
prints acceptance/IDs only, verifies HTTPS, rejects redirects, and never retries.
On unconfirmed acceptance, inspect execution history **before** retrying: execution
may already have started. `ACCEPTED` is not a redaction pass. CLI v1.37.0 cannot
invoke deployed workflows; `workflow simulate` is local, not staging/Nitro evidence.

Require the intended diagnostic for **each** app/case, not merely an absent marker:

| App | Redirect | Certificate |
| --- | --- | --- |
| Confidential HTTP | `error in request 0: error making http request: redirects are not allowed` | `error in request 0: error making http request: TLS certificate hostname mismatch` |
| Confidential Workflows | `http-actions: http request failed: redirects are not allowed` | `http-actions: http request failed: TLS certificate hostname mismatch` |

Standalone errors have enclave app code 400, not an upstream HTTP status; node
wrappers may add context or collapse redirects to `redirects are not allowed`.
For Workflows, the outer enclave request may succeed while the SDK result fails.
Check the failed HTTP step, not just gateway/outer-request status.

Usable responses, synthetic statuses, DNS/policy/connection failures, missing
executions, and `redaction smoke expected a hard failure, got HTTP ...` are not
passes. Resolve endpoint/access issues before rerunning.

Find the execution by its trigger ID/UTC window; confirm `HTTP redaction smoke
started` and the failed step. Set `EXECUTION_ID` to the execution UUID returned
by the list command, which may differ from the gateway's workflow-execution ID:

```bash
cre_staging execution list "$NAME" --start "$TRIGGER_START" --target=staging-zone-a
# Set EXECUTION_ID from that list before exporting.
: "${EXECUTION_ID:?set the execution UUID for this case}"
PREFIX="$EVIDENCE_DIR/$APP-$NAME-$CASE"
cre_staging execution status "$EXECUTION_ID" --target=staging-zone-a --output json > "$PREFIX-status.json"
cre_staging execution events "$EXECUTION_ID" --target=staging-zone-a --output json > "$PREFIX-events.json"
cre_staging execution logs "$EXECUTION_ID" --target=staging-zone-a --output json > "$PREFIX-logs.json"
```

In Grafana Explore, use the label browser for actual staging workflow-node and
enclave-host/plugin streams; bound queries by UTC window and workflow/execution ID.
Inspect full error records. Release Nitro guest stderr/kernel logs are **not in
Loki**; do not enable debug mode or weaken attestation. Use accessible host/plugin
logs, workflow results, and forwarded response/Beholder events.
The node debug log `emitting capability_finished beholder event` has `success`/`error`;
`workflows.v2.CapabilityExecutionFinished` carries `Error`
([source](../capabilities/framework/capability_events.go)). If debug logs are not
collected, use the authorized Beholder viewer/export. For standalone certificate
failures, also inspect `enclave execution failed` and the failed capability step.

Add relevant Grafana/error/event exports, excluding inputs/configs/keys and endpoint
preflight output. Run `rg -n -F 'cc-redaction-smoke' "$EVIDENCE_DIR"`: no marker in
failure diagnostics. Save positive intended-error evidence, workflow IDs, UTC windows,
and Explore/UI links. Empty queries or inaccessible sources are gaps, not passes.

### Clean up each deployment

After saving evidence for **both** cases, delete this smoke before changing its
workflow YAML or deploying the other app:

```bash
cre_staging workflow delete smoke --target=staging-zone-a
```

Check the confirmation names only this smoke. After both apps, confirm both
workflows are deleted, retain evidence outside `SMOKE_ROOT`, then remove the
disposable project/key with `rm -r "$SMOKE_ROOT"` and `unset AUTHORIZED_KEY`.

### Local coverage

Use deterministic local tests for post-header timeout/truncation, not a new staging
fault-injection server:

```bash
cd "$CC_REPO"
mkdir -p "$HOME/tmp"
TEST_TMP=$(mktemp -d "$HOME/tmp/cc-redaction-tests.XXXXXX")
export TMPDIR="$TEST_TMP" GOTMPDIR="$TEST_TMP" GOTOOLCHAIN=go1.27.3 GOMAXPROCS=1 GOFLAGS='-p=1 -mod=readonly'
(cd tests/e2e/testdata/workflow && GOOS=wasip1 GOARCH=wasm CGO_ENABLED=0 go build -mod=readonly -p 1 -o "$TEST_TMP/redaction.wasm" ./redaction)
(cd tests/e2e/testdata/workflow && go build -p 1 -ldflags='-s -w' ./... && go test -p 1 ./redaction/input -count=1)
(cd tests && go test -p 1 ./e2e/cmd/http-trigger -count=1)
go test -p 1 ./util ./enclave/apps/confidential-http/app -count=1 -run '^(TestSanitizeOutboundHTTPError(_ReadFailures)?|TestClassifyOutboundHTTPError|TestHTTPEnclaveApp_Execute_(RedactsHTTPFailures|RedirectRejected))$'
(cd enclave/apps/confidential-workflows && go test -p 1 ./httpfetch ./app -count=1 -run '^(TestFetch_(RedactsErrors|RealHTTPFailuresAreRedacted|SyntheticResponsesRemainRedacted)|TestExecute_HTTPFailureDoesNotDiscloseRequestData)$')
unset TMPDIR GOTMPDIR
rm -r "$TEST_TMP"
```

Input/helper tests cover fixed cases/URLs, signed case/workflow binding, key-file
safety, HTTPS/redirect enforcement, acceptance handling, and no retries.
`TestFetch_RedactsErrors` / `TestHTTPEnclaveApp_Execute_RedactsHTTPFailures` cover
timeout/truncation, discarded partial bodies, and redacted errors.
`TestExecute_HTTPFailureDoesNotDiscloseRequestData` covers real WASM, logs, and
`capability_finished` events; local HTTPS tests assert redirects are not followed.
Go 1.27.3 avoids the known Go 1.27.4 Wasmtime LTO incompatibility without security
overrides. None of these prove staging execution or staging read-fault coverage.

## Success criteria

- All four staging app/case combinations produce the intended sanitized failure,
  with no marker in failure diagnostics/logs/telemetry, and have saved evidence.
- Focused local tests pass, including hard response-read failures, discarded
  partial bodies, redirect blocking, and unchanged synthetic responses.
- Existing success canaries remain healthy; all smoke workflows and the disposable
  signing key are removed.

## Edge cases and risks

Public endpoints may be unavailable or blocked from staging; wrong failure
categories are inconclusive. Never send real secrets to these endpoints. Unknown
failures intentionally lose raw details. Workflow-authored request logs, public
inputs, and successful payloads are outside this redaction boundary. Destination
hostnames/IPs/ports remain visible to the host; this change redacts errors, not
network metadata. A marker in failure diagnostics or a changed failure
classification blocks release.
