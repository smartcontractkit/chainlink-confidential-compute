# Staging validation: bump-chainlink-3deeb0e9

## Change

Bumps chainlink-common to `e76ab5ff9b42` in every module: the merge of main
into the `conf_http_direct_secrets` branch of chainlink-common PR #2527, which
adds `ConfidentialCompute.ConfidentialHTTPVaultGetSecretsDirectlyActivePeriod`
(the confidential-http direct-read gate used by the follow-up executor change)
on top of the per-capability Confidential Compute overrides (#2528). The pin is
the pre-merge branch commit; re-pin to the merged main commit once #2527 lands.
Also bumps the chainlink E2E pin to `3deeb0e9da`, which adapts chainlink to the
orgresolver and multichain-key changes in newer chainlink-common (#24170,
#24192); that part is test-only.

Adds `//nolint:staticcheck` for the three beholder global reads
(`GetEmitter`/`GetMeter`) in the framework and enclave-client: the common bump
deprecates the global accessors (DX-5066), but LOOP plugins still receive the
client via the process global until the loop protocol passes it in.

## Validation steps

- Deploy the confidential-workflows and confidential-http enclaves to staging and confirm all enclaves come up and reach quorum.
- Watch the existing confidential-workflows and confidential-http canaries for at least a day.
- Confirm each capability's `resolved capability config` log still shows the expected per-capability Confidential Compute limits.
- Confirm vault `GetSecrets` requests from confidential-http still show `get_secrets_directly: false` (the new gate defaults off; behavior is unchanged).

## Success criteria

- Canaries stay green, with no new execution failures.
- Resolved Confidential Compute limits are unchanged from the previous release.
- Confidential-http vault requests remain on the OCR path.

## Edge cases and risks

- The chainlink-common pin is a pre-merge branch commit; if #2527's merged version differs, re-pin and redeploy.
- The chainlink E2E pin moves ahead of the last validated release (196850e); watch CI e2e legs for drift.
- Rollback: redeploy the previous enclave release.
