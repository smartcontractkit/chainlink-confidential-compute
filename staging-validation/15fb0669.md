# Staging validation: pr-117-host-binary-fetching

## Change

The host downloads and caches workflow binaries; the enclave verifies their
SHA-256 against DON-signed public data before executing. Storage settings are
startup-only; changes through `/settings` return 409 and require a host restart.

## Validation steps

- Deploy the host and confidential-workflows enclave together to a drained canary.
  Set `BINARY_CACHE_DIR` to a writable persistent volume; each enclave CID gets
  its own subdirectory, exclusively owned by one host process.
- Run a workflow cold, warm, and after host restart. Repeat with storage unavailable
  after warming. Confirm downloads occur only on cache misses.
- Corrupt a cached `.bin`, rerun with storage available, restart, then rerun with
  storage unavailable. Confirm repair persists. Supply a mismatched host binary
  in a test environment and confirm the enclave rejects it before compilation.
- Exercise concurrent distinct workflows with a small cache bound; compare `.bin`
  bytes with `BINARY_CACHE_MAX_BYTES`. Zero uses `maxCacheBytes` from settings,
  otherwise the 256 MiB default. Inject changed storage settings and expect 409;
  restart with the new settings and verify the new identity works.
- Confirm invalid signatures and below-quorum batches trigger no downloads;
  storage failures reach every waiter, and retries recover once storage returns.

## Success criteria

Valid workflows produce unchanged results. Tampered binaries never execute.
Cache contents survive restarts and stay within the per-enclave byte bound;
interrupted writes are removed at startup. HTTP/echo requests remain compatible
with legacy array-based enclaves. Storage errors do not strand pending batches.

## Edge cases and risks

Workflow versions must be coordinated: old hosts supply no binary, and old
enclaves reject the new envelope. Drain and roll back both together on failures.
Do not share a CID directory between live hosts. Storage and disk are untrusted
for integrity; cache writes are best-effort, and unavailable storage still fails
cold requests. Disk I/O is serialized to keep eviction and accounting coherent.
Staging and real Nitro validation remain required before release.
