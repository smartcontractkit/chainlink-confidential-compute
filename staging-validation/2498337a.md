# Staging validation: conf_http_direct_secrets

## Change

Adds a capability-side active-period gate for the Confidential HTTP Vault
`GetSecrets` pre-fetch path:
`ConfidentialCompute.ConfidentialHTTPVaultGetSecretsDirectlyActivePeriod`.
The capability uses direct reads only when this gate and the existing
per-workflow `PerWorkflow.FeatureVaultGetSecretsDirectlyActivePeriod` are both
active for the execution timestamp. `GetSecretsDirectly` is set on the request
only when true, so the gate-off payload is unchanged. Ships in the
confidential-http capability binary; no enclave, relay, or vault changes.

## Validation steps

1. Enable `FeatureVaultGetSecretsDirectlyActivePeriod` in staging and make sure
   the Confidential HTTP canary still works and is going through the OCR
   `GetSecrets` path. In the vault logs, the
   `received workflow get secrets request` line should show
   `get_secrets_directly: false`, with no `served direct get secrets request`
   line for the canary.
2. Enable `ConfidentialHTTPVaultGetSecretsDirectlyActivePeriod` and make sure
   the Confidential HTTP canary remains at 100% and latency drops for the
   Confidential HTTP calls. In the vault logs, requests should now show
   `get_secrets_directly: true` and `served direct get secrets request`.

## Success criteria

- With `FeatureVaultGetSecretsDirectlyActivePeriod` enabled and
  `ConfidentialHTTPVaultGetSecretsDirectlyActivePeriod` disabled, the
  Confidential HTTP canary succeeds on the OCR `GetSecrets` path.
- With both flags enabled, the Confidential HTTP canary remains at 100%,
  requests use the direct `GetSecrets` path, and Confidential HTTP latency
  drops.
- Resetting `ConfidentialHTTPVaultGetSecretsDirectlyActivePeriod` to the off
  period immediately returns Confidential HTTP to the OCR path.

## Edge cases and risks

- The global flag is already on. Keep the capability gate off until every
  capability DON shard is upgraded; otherwise old nodes send `false` and new
  nodes send `true`, splitting the payload hash and potentially preventing the
  vault-side `F+1` identical-request quorum for the minority group.
- Use a future active-period start and confirm settings propagation before
  activation so all nodes flip together.
- The gate is global, so all Confidential HTTP workflows and capability DON
  shards change together.
- If direct reads cause errors or latency regressions, reset the gate to the off
  period; no binary rollback is required.
- Enclaves and the relay are unaffected; only the capability's vault request
  changes.
