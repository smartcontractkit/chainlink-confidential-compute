# Staging validation: cw-workflow-result-metric

## Change

The confidential-workflows enclave adds an `outcome` attribute (`success`, `workflow_error`, `error`) to the existing `workflow_guest_execution` event. The capability plugin re-emits it as OTel metrics with the usual `org.id`/`workflow.id` labels. `workflow_error` marks runs where the workflow returned an error, which today look identical to clean runs. That makes it the signal for the PRIV-758 per-org error-ratio alert that INCIDENT-2784 lacked.

## Validation steps

- Deploy the confidential-workflows enclave to staging.
- In Grafana, query the confidential-workflows `workflow_guest_execution` counter (component `enclave`) grouped by `outcome` and `org.id`.
- Trigger the confidential-workflows canary, plus a workflow that returns an error (for example an HTTP call to an unreachable host whose error the workflow returns).

## Success criteria

- Canary runs appear under `outcome="success"`; the erroring workflow appears under `outcome="workflow_error"` with `success="true"`.
- A runtime timeout appears under `outcome="error"` with `success="false"`; error-path metrics may lack org/workflow labels, so verify the system-error series separately.
- Existing panels using `success` or the duration histogram are unchanged in totals.

## Edge cases and risks

- Adds one bounded label (three values) to an existing counter and histogram, so series count grows at most threefold for this event.
- No behavior change to execution. Rollback: redeploy the previous enclave release.
